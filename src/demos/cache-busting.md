## How It Works

Browsers are fastest when they don't ask the server for a file at all. A `Cache-Control: max-age=31536000, immutable` header tells them exactly that: keep this file for a year, don't even check whether it changed. The catch is in the name. If `main.css` changes but its URL doesn't, every returning visitor keeps the old one for up to a year.

This site used to have exactly that bug. Its `netlify.toml` marked everything under `/assets/` as immutable, while `main.css` and `main.js` kept the same URLs on every deploy. The fix is to make the URL change whenever the content does, and only then promise the browser it never will:

{% raw %}

```njk
<link rel="stylesheet" href="{{ '/assets/scss/main.css' | assetUrl }}">
<script type="module" src="{{ '/assets/js/main.js' | assetUrl }}"></script>
```

{% endraw %}

`assetUrl` is an ordinary custom filter. It hashes whatever the file's content depends on and appends it as `?v=…`:

- **The JavaScript** is bundled by esbuild in an `eleventy.before` hook, so the finished bundle already exists before any template renders. The filter hashes the bundle itself.
- **The CSS** is compiled by Eleventy alongside the pages, so it may not exist yet when a page asks for its URL. Instead the filter hashes everything the CSS is made from: every `.scss` file, the Sass extension that compiles them, and the Sass version. The same inputs always give the same CSS, so that hash works just as well.

Then `netlify.toml` sets the long-lived header only for paths where every URL is versioned or hashed, and nothing else:

```toml
[[headers]]
  for = "/assets/js/*"
  [headers.values]
    Cache-Control = "public, max-age=31536000, immutable"
```

Images get the same treatment for free: the {% demoLink "automatic-images", "image plugin" %} and the {% demoLink "social-images", "social cards" %} both put a content hash in every filename they write, demo thumbnails included, so those are cached for a year too. The few files that keep plain names, like the favicons and the web font, get a one-day cache or Netlify's default of checking for changes on every request.

```text
src/_11ty/filters/assetUrl.js  ← the filter, and what each URL's hash depends on

src/_11ty/scripts.js           ← esbuild bundling, run from eleventy.before
src/_includes/layouts/base.njk ← where every page asks for its asset URLs
netlify.toml                   ← which paths are safe to cache forever

```

## Notes

- Why a query string instead of a hashed filename like `main.3f9a1c.css`? Hashed filenames need a manifest that maps the real name to the hashed one, and the CSS is generated by Eleventy itself. A query string keeps every file at its normal path, which also keeps `codeFile` and dev tools simple. Netlify serves the same file for any query string, and its CDN cache is cleared on every deploy, so the only cache the `?v=` needs to defeat is the browser's.
- HTML pages are never cached long-term. They're served with Netlify's default `max-age=0, must-revalidate`, so a visitor always gets fresh HTML, and fresh HTML always points at the current hash.
- The filter throws if you ask it for a URL it doesn't know how to fingerprint. An unversioned URL on a path that's cached for a year is the exact bug this demo is here to fix, so it's better to fail loudly.
