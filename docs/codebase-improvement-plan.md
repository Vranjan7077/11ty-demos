**H2 details.** Netlify Blobs 10.7 supports conditional writes: `getWithMetadata` returns an ETag, and `set` accepts `onlyIfMatch` / `onlyIfNew` and reports `modified`. Reads use `consistency: "strong"`. The function increments by read → conditional write → retry, up to 5 attempts, which is optimistic concurrency, not a lock. If it loses the race five times it returns `503` with `Retry-After` and never writes a wrong number. The client `POST`s once per tab session (`sessionStorage`) and uses `GET` after that. The key allowlist is `view-counter-demo`; the old default key `site` is now rejected, and nothing in the site used it. No stored data was changed or deleted.

**H4 details, applied in this order:**

1. `npm update` + `npm audit fix` (non-breaking). This took advisories from 14 to 3 (fixed markdown-it, js-yaml, brace-expansion, source-map-js, @fastify/busboy, @opentelemetry/*, shell-quote).
2. `@11ty/eleventy-img` 6.0.4 → 7.1.1. It brings sharp 0.35.5, which fixes the libvips/libheif/librsvg advisories, and requires Node 22 or later, hence H3 first.
3. Removed `terser` and `npm-run-all2` (replaced by esbuild and plain `&&`, see P1). Added `esbuild` 0.28.2 and `@11ty/eleventy-fetch` 6.0.1.
4. Deferred: `@netlify/blobs` 11 (see below), `eleventy-plugin-rss` 3, `markdown-it-anchor` 10, `dotenv` 18, `cross-env` 10. None has an advisory, and all are majors with unverified breaking changes.

## Remaining risks and limitations

- **Netlify-only behaviour is unverified:** response headers, `_headers` merging, the function against real Blobs, and git history depth for F3. All need the first deploy preview (manual checks below).
- **Counter concurrency:** increments are compare-and-swap with five attempts. Under extreme contention a visit gets a 503 rather than being counted. That's correct but lossy, and fine for this page.
- **CI** hasn't run on GitHub yet. Locally, `npm run check` reproduces every step except `npm ci` on Linux.
